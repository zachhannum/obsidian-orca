The marks Obsidian does not draw

A chapter carries five run forms and two break commands that fleuron's obsidian dialect reads and Obsidian draws as prose. Orca draws a run as a chip that names it and a break as a rule across the measure, in the editor and in reading view alike, so a mark the book is set by is visible in the note it lives in. The chip names a run the way inspect mode names a box: the id, then the classes, and never the braces.

Every run in the note is drawn where it was written: a line of its own becomes a chip on that line, a run at the end of a heading becomes a chip at the end of the heading, and a run on an image sits under the image. A setext underline is the one mark the editor keeps, because the line is still there to type on. A break command is a rule across the measure, named for the command it came from.

The line the caret is on shows its source, the way Live Preview shows every other mark. The rest of the note keeps its marks, so moving the caret reveals one line and disturbs nothing around it. A break command reads the same way: the caret on its line shows \pagebreak, and the rule comes back when the caret leaves.
A break is a rule. \pagebreak and \columnbreak at the head of a line of their own draw a rule across the measure, named for the command. The page break's rule is solid and the column break's is dashed, so the two read apart at a glance. A command indented four spaces is the code block it is, and one written inside a paragraph is the prose fleuron paints.
A chip names its run. The id first, as #fifteen, then each class in written order, as .chapter-opening. The id is accented and the classes are faint, which is how inspect mode tells them apart on a page. A run with no id shows its classes alone, and a run with no class shows its id alone. The braces are not drawn, because the chip is where they were.
Only in a book's note. The editor draws these marks in a note a book reads. A note no book lists is a note, and Obsidian draws it as Obsidian draws it: the run stays the prose it always was, in both views.
The engine says where a run is. The marks come from fleuron's parse of the note, so orca has no markdown parser of its own and a run the engine did not read stays prose. ==highlight==, %% comment %%, #tag and $math$ are drawn exactly as Obsidian draws them, with no mark and no warning, because the engine is the only linter.
